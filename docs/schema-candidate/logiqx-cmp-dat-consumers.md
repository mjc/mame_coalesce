# Logiqx, CMP and No-Intro source-free consumer reconciliation

Status: MAMEC-62 design note. Current source establishes behavior exposed today; candidate DDL and canonical ledgers define the target. This does not claim the candidate is installed, that current readers query it, or that authentic imports meet its capture requirements. Exact target values, presence states, count events, parent keys and position codes remain in the ledgers and SQL. This is a consumer crosswalk, not a second field inventory or a source-reparse path.

## Shared identity and query boundary

Current entry points are `app::{import_dat,import_catalog,catalog_snapshot_history,diff_catalog_snapshots,load_snapshot_source}` in `src/app.rs`. Paged readers are `catalog_logiqx::reader::logiqx_for_snapshot`, `catalog_clrmamepro::reader::sets_for_snapshot`, `catalog_no_intro_dat::reader::games_for_snapshot`, and `catalog_no_intro_database::reader::games_for_snapshot`. They validate a published snapshot/registry generation and hydrate a bounded page. The last is observed database-export XML, not synthetic P/C. P/C has history/fixture support, no public paged reader.

The target starts source-free reads at published `catalog_editions.edition_id`, uniquely identified by `(catalog_id, source_file_id, reading_rules_id, coverage_id)`. Family documents key by edition; shared `catalog_set_groups`/`catalog_sets` own roots, game names and placement; family game rows key by the same `set_id`; media payloads key by `catalog_media_entries.media_entry_id`; hashes/positions and source links retain their actual declaration owners. `catalog_source_files.source_file_id` identifies the retained original. `catalog_imports.import_key` identifies every attempt, including verification/re-import, but is neither content ownership nor a history sort key.

Do not use a cursor, generated ID, filename, declared hash or registry label as edition identity. Preserve documented page order: Logiqx set/child order; CMP form and mixed ROM/sample order; flat-DAT game/header order; export game/header placement. Target `source_order` is parent-local and retains accepted raw gaps. CMP form order, set-item order, field-local order and decoded-text coordinates remain distinct. Do not synthesize dense ranks or copy ancestor IDs onto descendants.

Target reads are committed-edition reads. Pages take an explicit edition and bounded cursor; history/diff take explicit edition keys. Provisional rows, import-attempt order, receipts and source-file update time are not catalog content.

## External metadata, physical root and declarations

Current `load_snapshot_source` returns retained original bytes; the source hash/length describe those bytes, not producer metadata. `logiqx_documents` owns the physical root; compatible-only `logiqx_root_file_names` and `logiqx_root_sha1_elements` preserve root declarations. The declared SHA-1 is an unknown-scope source claim in `hash_values`, never the XML byte digest or media identity. Pinned DTD 1.5 rejects these compatible children; current compatible parsing accepts them.

`clrmamepro_documents` owns CMP's physical document and top-level form order; `clrmamepro_headers` / `clrmamepro_header_options` own header values under pinned `compat-v1`. Preserve ignored/extension form slots accepted by that reader. Flat DAT uses distinct `no_intro_dat_documents` root and `no_intro_dat_headers`; current source proves an opening location only, while the candidate's complete root interval is optional. `no_intro_pc_documents`, `no_intro_pc_headers` and typed header values describe only the synthetic fixture adapter, never authentic DAT-o-MATIC syntax.

Root extents are optional and view-qualified. Logiqx needs matching `<datafile>` endpoints. CMP includes comments, outside-form material and BOM; retained-original byte offsets require a verified decoded-to-original mapping. Flat DAT needs both endpoints in one declared view. Unknown mapping means no byte extent, not a reconstructed offset.

Request-scoped diagnostics and source anchors use the same actual ancestry. The writer selects errors/messages for the active import, attaches an ordinary diagnostic only to its proven `catalog_source_elements` owner, and uses the format's real root owner only for a proven root diagnostic. Extent containment is checked only when both ranges share a mapped view; an EOF endpoint cannot claim containment. A message with no proven owner remains source-only. Candidate field/owner/order/hash/relationship/count closure runs against the exact edition before publication; global orphans stay global findings rather than being assigned to this request by matching names or coincident IDs. Source-free readers consume committed owners/links and never recreate missing anchors from the original.

## History, diff and source-free ordering

`app::catalog_snapshot_history` currently orders by document key, interpretation key and snapshot key, returning declared version and coverage. The proposed published-edition ordering and explicitly changed response identities are single-owned by [query-contract.md](query-contract.md); do not define a competing identity sort here. Version text or import attempt time is not semantic chronology. Keep declared version only under the existing export rule: exactly one header version yields a value; absent/repeated yields `None`.

`app::diff_catalog_snapshots` requires two snapshots in one catalog and the same root-versus-software family. It compares scope and document metadata, groups repeated set names, and includes reported relationship explanations. Unique names receive direct field/requirement comparison; duplicate names use exact fact-multiset correspondence or are ambiguous. Target history queries the two published editions and compares canonical values/owners/relationships; it does not persist history JSON. Preserve public status/correspondence and coverage-aware added/removed/unknown/out-of-scope distinctions.

`records()` assembles family projections into JSON maps keyed by generated set IDs. Logiqx/flat DAT normalize retained child ranks; CMP derives sample ranks from `asset_occurrences`; P/C maps fixture field codes. Target reconstructs from typed rows: details retain physical positions, history compares semantic values and relative native order while ignoring unowned gaps, coordinates and generated ranks. CMP status is derived; P/C stays fixture-only.

History equality includes retained source values, meaningful explicit/default presence, declared digest algorithm/value and owner, relationship target/provenance, repeats and relevant native order. Exclude generated database IDs, snapshot/edition/import keys, attempt time/status, fetch/acquisition receipts, transport URL, retained-byte hash/length, source coordinates/extents, parser buffers, ignored unknown subtrees, synthetic ranks and audit/count rows. Logiqx `file_name` and declared root `sha1` are source content and remain comparable. CMP `source_block` spelling and form ordering remain content. A comment's physical coordinate orders it, but does not alone change history if text and relative lexical sequence are unchanged.

## Ownership decisions and open boundaries

| Current projection fact | Decision |
|---|---|
| Snapshot keys, snapshot-specific family tables, generated numeric IDs | Reshape to edition, shared set/group/media IDs and typed native owner keys. |
| Current set/list/occurrence order, field codes and typed values | Retain public meaning on candidate native owners/position relations with parent-local `source_order`; see canonical owner/field/presence/hash ledgers. |
| CMP effective status and No-Intro scalar interpretation | Derive from retained source text, flag/XSI declaration and pinned reading rules; do not persist duplicate effective values. |
| CMP comment text/coordinate, field spelling and quote bit; Logiqx declared root SHA-1 | Retain existing captured facts on native owners. Current optional root SHA-1 bytes map to `logiqx_root_sha1_elements.hash_id` → `hash_values.bytes`, not to the computed original-document digest. Typed declaration ownership is reshaped, not newly discovered content. |
| CMP keyword coordinates; typed physical root/declaration owners and complete extents; DAT XSI QName/type resolution | New candidate capture/ownership facts beyond current public model. Consume only after future reader capture and EOF proof; retaining current comment/spelling/quote values alone does not prove these additions. |
| History JSON, generated child ranks, copied parent/group IDs, field-name caches, duplicate hash copies, raw payload/token/DOM storage | Retire as storage; reconstruct API values from native owners and canonical maps. |
| Attempt/acquisition timeline, source transport/retry facts, unknown syntax and unsupported formats | Exclude from catalog source-free content/history; keep receipts/attempts only in their distinct operational owners. |

The candidate deliberately has no computed document hash beside Logiqx declared root SHA-1; no original-byte coordinate inferred from decoded XML without verified mapping (coordinates measured directly in a declared decoded view remain valid in that view); no CMP value text/coordinate for keyword-only flags; no fabricated comment parent/rank; nullable flat-DAT root extent where endpoints are unproved; and no P/C grammar beyond the existing synthetic fixture. Its XSI target stores `source_qname` and closed `resolved_type_kind`, not a general namespace-binding table or arbitrary resolved-type string. These are explicit design boundaries, not values to backfill by reparsing at query time.

Current code does not prove target capture/parity: Logiqx drops ignored root-child gaps; CMP buffers forms, strips accepted BOM before lexing and lacks keyword coordinates; decoded text does not establish original-byte mapping; flat DAT lacks a complete physical root extent; SQL counts are not independent parser counts. These are capture/publication proof items, not a reader reparse path. Separately, the observed export ledger has 135 literal fields and already includes both `nfo_crc32` and `nfocrc`; an unlocated CSV claims 137. The two unnamed fields are a count-evidence contradiction, not identified target omissions. Do not invent owners; reconcile only against that exact versioned CSV if recovered. Authentic P/C remains unsupported.
