# MAME and software consumer reconciliation

Status: design contract for MAMEC-62 / MAMEC-PLAN-3 #2074. It maps current public queries/history to candidate DDL; current Rust still reads the existing schema. Candidate names are proposed owners, not an implemented target. “Source-free” means no XML reopen is needed.

Canonical field/owner/presence/hash/count/relationship inventories are in `mame-field-coverage.tsv`, `mame-field-presence.tsv`, `mame-hash-positions.tsv`, `mame-owners.tsv`, and corresponding software ledgers. This maps returned families to those owners without repeating field-code lists.

## Identity and API boundary

APIs: `machines_for_snapshot` (`src/storage/catalog_machines.rs:251`, reader `src/storage/catalog_machines/reader.rs:374`); `lists_for_snapshot` / `titles_for_list` (`src/storage/catalog_software.rs:598,665`); `catalog_snapshot_history` / `diff_catalog_snapshots` (`src/app.rs:846,837`), implemented by `history` / `diff` (`src/storage/snapshot_history.rs:1754,973`). Query anchors: `src/storage/catalog_machines/queries.rs` (`MACHINE_COLUMNS`, `BIOS_SETS`, `CLONE_LINKS`, `DEPENDENCIES`, asset, switch, `SPEC_*` constants); `src/storage/catalog_software/queries.rs` (published snapshot, page, selected list, title, part, switch, area, ROM, disk constants). sem context confirmed bodies and dependencies.

Page APIs take a published snapshot key. Target is `catalog_editions.edition_id` gated by `published_catalog_editions`; edition owns catalog/source/rules/coverage/receipt/predecessor. Related tables: `catalogs`, `catalog_source_files`, `catalog_reading_rules`, `catalog_coverage`, `catalog_covered_sets`. Never substitute latest. Page provenance also reads `mame_documents` or `software_documents`, plus plural `software_wrapper_headers`. MAME document owns build, debug/presence, `mameconfig` and root coordinates/extents; software document owns envelope, plural wrapper owns wrapper build. Results include source/catalog/document/interpretation/scope.

MAME identity/order/location: root `catalog_set_groups` → `catalog_sets(set_id,set_name,source_order,source_line,source_column)` → `mame_machines.set_id`. Software list: `catalog_set_groups.set_group_id` / `software_lists.set_group_id`; title: `catalog_sets.set_id` / `software_titles.set_id`, scoped to list. Names are not IDs. Bind local IDs/cursors to registry generation, snapshot and (for titles) list. Current ties: MAME `(list_order,set_id)`, lists `(list_order,set_group_id)`, titles `(list_order,set_id)`. Candidate has no `list_order`: plural list order is `software_list_wrapper_entries.source_order`; singular has one list; title order is `catalog_sets.source_order`. Pages cap at 500 and include all children of selected titles. No arbitrary machine-ID lookup is public.

## MAME machine result mapping

|---|---|

Keep values/presence paired. `mame_machine_compatibility.isconsumable`; absent row reads false/unspecified. |
| Description/year/manufacturer and locations | `mame_machine_text_elements(machine_id,field_kind,text_value,source_order,source_line,source_column)`; description required, year/manufacturer optional. |
| BIOS sets and defaults | `mame_bios_sets(machine_id,name,description,default,default_specified,source_order,location)`; retain explicit default presence. |
| Clone/rom/sample links and device references | `mame_machine_links` owns declared names/relationship IDs; `mame_machines_attribute_positions` supplies link field, source order and location. `mame_device_references` owns name/tag/order/location and its relationship. Route via `reported_catalog_relationships` / `catalog_relationships`; names are not resolution. |
| ROM/disk/sample occurrences and asset values | `mame_roms`, `mame_disks`, `mame_samples` keyed by `media_entry_id`, parent `machine_id`; join `catalog_media_entries` and occurrence. Return occurrence ID, kind, order and location, not copied payload. Hash/presence/scope use `catalog_entry_hashes` → `hash_values` and the hash ledger. Checked size/offset derive from retained text; malformed/overflow text remains uninterpreted. ROM/disk compatibility stays in `mame_rom_compatibility` / `mame_disk_compatibility`. |
| Switches, values, conditions, locations | `mame_switches` with typed children `mame_switch_locations`, `mame_switch_values`, `mame_switch_conditions`, `mame_switch_value_conditions`. Retain child owner/order and default/inverted presence; switch, value and adjuster conditions differ. |
| Specification variants | The 13 `MachineSpecification` families map to `mame_samples`, `mame_chips`, `mame_displays`, `mame_sound`, `mame_inputs` + controls, switches, adjusters + conditions, ports + analogs, drivers, features, devices, slots + options, software-list references and RAM options. Sample is the same `mame_samples` media owner, not another stored row. Use actual parent FKs and `source_order` for mixed and nested order. Field/default meaning is in the MAME ledger; do not flatten or add EAV ownership. |
| Device instances/extensions | `mame_device_instances(device_id,name,briefname,source_order,location)` and `mame_device_extensions` are separate `mame_devices` children. Strict DTD permits at most one; `observed-v3` retains every accepted instance; historical `observed-v2` is first-instance loss. Current parser is not v3. Do not apply strict cardinality/order to v3. |
| Typed attributes and positions | Per-owner `*_attribute_positions` tables named by `mame-field-presence.tsv`; hash positions point to exact `reported_hash_id`. Values remain on typed rows. Current `attributes::machines` returns typed positions and checks ownership/order closure; candidate ledgers are build-time definitions, not runtime rows. |

`load_machine_children` (`reader.rs:642`) assembles selected owners’ children, attributes and positions, then validates closure. Target reads must constrain children to selected `set_id`s and join by owner key; `source_order` is not identity.

## Software list/title mapping

| Current returned family | Candidate owner / mapping |
|---|---|
| Root, envelope, lists | `software_documents(edition_id,envelope_kind,extent/location)`. Singular root is a `software_lists` group without a wrapper. Plural root uses `software_wrapper_headers` and ordered `software_list_wrapper_entries(wrapper_id,set_group_id,source_order)`. `software_lists` owns name, optional description and root coordinates/extents. |
| List notes/text/attributes | `software_list_notes(set_group_id,text_value,source_order,location)` owns notes presence, text (including empty text), child order and location. `software_list_attribute_positions` records list attributes such as name/description, not notes. There is no separate notes-position row. |
| Titles and required text | `catalog_sets` plus `software_titles(set_id,supported,supported_specified)`. `software_title_text_elements` owns description/year/publisher/notes; required empty strings are values. `software_title_attribute_positions` owns attribute presence. Unspecified supported defaults to yes. |
| Clone, info, shared features | `software_clone_links(set_id,target_name,relationship_id)` routes the declared name through reported relationship identity, without name-only resolution. `software_title_info` and `software_shared_features` own ordered name/value pairs; nullable value distinguishes name-only from valued entries. |
| Parts, features, DIP switches | `software_parts(set_id,name,interface,source_order)` → `software_part_features`, `software_part_switches`, `software_part_switch_values`. Preserve parent/order, nullable value and default/presence. |
| Areas | `software_areas(part_id,area_id,kind)` has one detail owner: `software_data_areas` or `software_disk_areas`. Data returns raw `declared_size_text`, checked size, width/endianness and presence; disk has its own name/detail. Use `candidate_software_data_area_numbers`; ROM numeric projection is `candidate_software_rom_numbers`. Never replace text with a cast or misclassify disk area. |
| ROM/disk entries and hashes | `software_rom_load_entries` / `software_disks` join their typed area and `catalog_media_entries`. Preserve name, order, status/presence, raw lexemes, evidence scope and family-specific attributes. Hash slots are ROM CRC, ROM SHA-1, disk SHA-1 via `catalog_entry_hashes`; empty/invalid declarations are still source facts, not digest bytes. |
| Physical required-file/load interpretation | `candidate_software_rom_operations` derives operation/link state from ROM load instruction and `software_file_load_steps` / `software_required_files` represent checked chain/required-file closure. Ordinary loads declare one physical file; continue/reload/reload_plain/ignore follow the active declaration; orphan controls are not files; fill declares none and ends the chain. Disks are independent requirements, never ROM steps. Identity is a declared media occurrence, not one file per segment/reload or a hash inferred from segment bytes. Exact numeric grammar and NULL rules are in `software-notes.md`. |
| Attributes and sequence | Use typed position tables in `software-field-presence.tsv` / `software-hash-positions.tsv`. Actual FKs define ownership; parent-local `source_order` retains mixed sibling sequence. Derive public family-local list/title/part/area/component/value ordinals at read time within the actual parent and selected family, without persisting duplicate ranks. Never derive source order from generated IDs. |

`titles_for_list` resolves the list inside the exact snapshot before loading children. Preserve this closure across same-named lists/editions and return all children of selected paged titles.

## Semantic history contract

`history` currently orders by `(document_key,interpretation_key,snapshot_key)`, not version, and lacks a publication join. The proposed identity/publication ordering and explicitly changed response identities are single-owned by [query-contract.md](query-contract.md); do not define a competing source/rules sort here. `mame_documents.build` is descriptive, not identity. `diff` requires one catalog, rejects root/software-list pairs, and compares supplied editions—never pair by filename, version, name or generated ID.

Diff groups roots by name/order. Unique names compare metadata, regrouping, requirements and equal-cardinality MAME media-attribute changes. Repeated names compare exact signatures or report ambiguous/changed. Complete/equal-filtered published coverage establishes add/remove; partial, unknown, unpublished or excluded coverage yields unknown/out-of-scope. Use coverage tables, not predecessor links. Keep document metadata separate and attach explanations for relationships ending in either edition.

MAME history includes machine, BIOS, dependencies, switches/conditions, specification children and all 32 attribute families (`snapshot_history/mame_attributes.rs:FAMILIES`). Compatibility positions normalize to native machine/ROM/disk families but retain origin, field code and order. Equal-cardinality media edits are metadata; media add/remove is a requirement change.

Software history includes list/title, repeated-list context, text/attribute positions, info/shared-feature/part/feature/switch/area/ROM/disk children, clone and required files. Keep source order; normalize ROM uses to area-local rank. Current history includes named requirements only, size NULL, usable CRC/SHA-1 only, canonically sorted evidence; it is not byte verification. Document metadata compares header/build/envelope and presence/order, not source bytes. Extents/diagnostics are excluded. Assemble at read time; do not persist duplicate JSON.

## Ownership disposition and open proof

**Retain:** pinned pages/history, family values, order/location, default presence, declared hashes and comparison rules. **Reshape:** edition → group/set → typed owner/position/hash/relationship joins; IDs become candidate set/group/source-element/media keys; typed transient comparables replace current history JSON assembly. Required-file operation derives from ROM declarations. **Retire after parity:** duplicate aggregate owners, name-only relationship matching, persisted history payloads. Not a migration.

Gaps: no target query/history implementation or parity evidence exists. Current parsers lack full root extents/end coordinates required by MAME/software root owners; opening points cannot prove intervals, containment or diagnostic links. Numeric/hash/required-file projections and v3 instance semantics are design-only. If a returned field lacks an owner, block that consumer and add a native owner/projection; do not drop or invent it.

Acceptance: source-free parity for mapped families, absent/present-empty, defaults, invalid lexemes, repeated names, nested owners/order, compatibility, unresolved relations, page ties and cursor rejection. Check selected-ID closure. Diff all coverage states, unique/repeated names, regrouping, media edit vs add/remove, load chains, document metadata and stable order. Test observed-v3 multiple instances and strict-DTD cardinality. Assert values/provenance/order/exclusions; DDL/count witnesses do not prove runtime consumers, which must not reopen XML.
